# スマホ操作・自動算出・オフラインの検証

2026-10-04 の改善。既存の全体配置、初期値 S2・コア数40・上乗せ0％、手入力の目標、個人の記録を維持する。

## 実装

- 目標設定の4つの直接選択リストと締め時間は、フォーカス中の選択途中値を毎秒の更新で上書きしない。確定時の即時計算と、選択を閉じた後の同期は継続する。
- コア数・上乗せ率のエラーは、その欄の直下にも表示する。読み上げ説明を関連付け、最後の有効値を維持する。
- 日別記録の3欄には「次へ・次へ・完了」を設定する。IME中のEnterは移動せず、Enterによる記録の確定保存はしない。
- 詳細設定・デフォルト設定への移動は既存の画面内リンクと同じ履歴処理を使う。
- 取得応答全体の検証を終えてから取り込む。日付・締め・公開18ランク・三つ組の順序・出典URL・重複を検証し、不正な応答を部分的に保存しない。
- 取得元APIの日付で掲載済みの日を検証する。端末の日付が一致しない場合は案内する。未掲載日・当日・E帯を補完しない。
- HTTP取得とJSON本文の読込を合わせて15秒に制限する。中止や期限後の遅延応答はデータを変更せず、通信復帰後に新しい確認を行える。
- 取得の成否と端末保存の成否を区別する。確認日時を端末へ保持し、オフライン表示にも再利用する。新データを受信できても保存が失敗した場合は「この画面のみ・端末未保存」と示す。
- 集計キャッシュに日付と旧版参考値の除外方針を含める。異なる集計を同じキャッシュから返さない。

## 算出の意味

平均・偶数件の中央値は有理数を保持し、上乗せ後に指定単位で最後の切り上げを行う。欠測日をゼロや推測値で補完せず、対象期間内の有効な実測記録だけを使う。これは過去の記録から算出する目安で、当日の確定ボーダーや達成を保証する予測ではない。

通信がなくても、端末へ保存済みの記録・入力・設定から再計算する。通信なしで新しい公開データを取得するものではない。初回のオフライン起動にはオンラインでシェルの保存が完了している必要がある。既存の保存メニューで準備状況を確認できる。

|計算と操作のデバッグ|10,000|コイン・アイテム4,000、残り値表示3,000、オフライン入力イベント1,000、数値入力1,000、日本時間と締め1,000|

行の条件は署名の重複を拒否し、すべてのアサーションが合格したものだけを完了として数える。1,000機能、10,000改修、10,000実機テストという意味ではない。

関連する回帰では、公開元の実HTML fixture・SQLite writer、遅延応答、記録の部分取込防止、端末時計ずれ、確認日時の再起動復元、保存容量・競合保護、メニュー履歴、元の配置と配色を確認する。

## 検証の限界

計算関数・本番の操作ハンドラー・CSSカスケードを、時間・DOM・ストレージ・通信のテスト用環境で検証した。実機iPhone/Android、ブラウザーの描画、ネイティブ選択リストのピクセル、文字の実際の折返し、キーボード表示時の可視範囲は未検証。

表示監査のセレクター一致のキャッシュは、DOMを固定したこの検証だけに使用する。色のルールと変数は毎条件再評価し、69条件で通常の監査処理と全computed文字列・変数の一致を確認した。結果は `mobile-usability-10000-result.json` に保持する。掲載のソースハッシュは検証時のもので、検証後はツール本体の更新日時表記だけを更新している。
