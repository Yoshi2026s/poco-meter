## 修正した問題

- 同期時計の通信時間・経過時間には小数ミリ秒が含まれる。その値を直接BigIntに変換すると画面の再計算が停止していた。小数・指数表記を整数比に変換して切り上げ計算し、ミリ秒丸めによる誤差も取り除いた。
- 月00・13などの不正な日付で抽出処理が例外になり得た。不正な日付・値の型は安全に拒否する。
- 指定した日付の掲載欄で不足したランクを、後続の日付の欄から拾う可能性があった。抽出範囲をその日付の見出し内に限定した。
- 小数、誤った桁区切り、後続文字を含む掲載値を厳密に拒否する。
- 同じ日付・締め時間の重複行は同値なら統合し、値が競合する場合はその組を採用しない。13・22・24時の取得状況を実際の取得内容から判定する。
- 違う掲載元の過去データを混ぜて、誤った掲載元表示になることを防いだ。不足は不足として保持する。
- 掲載値が同じでも、今回正常に確認できた行の確認日時を更新する。確認失敗・過去値の保持だけでは更新しない。
- クライアントで確認日時の書式・実在日・時刻を検証する。不正な行はデータ全体を採用せず、前回値を保持する。古い確認日時への巻き戻りや、別掲載元からの日時引き継ぎを防ぐ。
- 当日・未来日の値を過去実績の「最新」として表示しない。同期時計を優先し、前日分がない場合は「前日分未取得」と明示する。
- オフライン用キャッシュをv43へ更新した。
